# sport_top Design Specification

## 1. Introduction

`sport_top` implements a Synchronous Serial Peripheral Port (SPORT) interface with separate transmit and receive serial channels and a host-programmable control interface.

The design supports:

- synchronous serial transmit and receive operation,
- primary and optional secondary serial data lanes,
- configurable frame-sync behavior (early or late framing),
- configurable frame-sync polarity,
- configurable serial bit ordering (MSB-first or LSB-first on transmit),
- host-driven configuration and data movement through FIFO-based buffering.

The module exposes a Wishbone-style host interface for configuration and data access, plus dedicated serial I/O pins for SPORT signaling.

### 3.2 Serial-Side Signal Semantics

- `TSCLKx` is driven from `txclk`; `RSCLKx` is driven from `rxclk`.
- `TFSx` and `RFSx` are generated by internal TX/RX frame-sync logic and optionally inverted based on active-polarity configuration bits.
- Early-frame mode asserts frame sync as a short pre-word pulse; late-frame mode asserts frame sync for the active data window.
- In secondary-channel mode, serial data for primary and secondary lanes is interleaved by software expectations.

### 3.3 Wishbone-Side Semantics

- Accesses use `wb_cyc_i`, `wb_stb_i`, `wb_we_i`, `wb_adr_i`, `wb_dat_i`, `wb_dat_o`, and handshake/status outputs `wb_ack_o`, `wb_err_o`, `wb_rty_o`.
- Configuration and data FIFO access are separated by address.
- FIFO write accesses can raise `wb_err_o` when FIFO-full conditions occur.
- Retry behavior is generated by the Wishbone interface block during write-cycle handling per its internal policy.

## 5. Function Description

### 5.1 Receive Path Operation

- RX logic is clocked by `rxclk` and outputs receive clock on `RSCLKx`.
- A receive state machine progresses through reset, idle, frame-sync, and receive phases.
- Serial data is shifted from `DRxPRI` and `DRxSEC` into internal shift registers each receive clock.
- Receive sample and packet counters advance during active receive state; increment step depends on single-channel or secondary-channel mode.
- `RFSx` is driven from internally generated frame-sync state and polarity control (`rx_actHi`).
- Early/late frame-sync selection is controlled by `rxlateFS_earlyFSn`.

### 5.2 Transmit Path Operation

- TX logic is clocked by `txclk` and outputs transmit clock on `TSCLKx`.
- A transmit state machine progresses through reset, idle, frame-sync, and transmit phases.
- TX word counters are driven by `txsampleCnt` and `txpacketCnt`; counter step depends on single-channel or secondary-channel mode.
- TX word data is loaded from FIFO-side data into two shift representations:
  - `word_outM` for MSB-first shifting,
  - `word_outL` for LSB-first shifting.
- `DTxPRI` outputs the primary serial bit stream; `DTxSEC` outputs the secondary stream when `txsecEn` is enabled, otherwise drives `0`.
- `TFSx` is generated from frame-sync logic with selectable early/late mode and active polarity.

### 5.3 Secondary-Channel Behavior

- Primary channels (`DTxPRI`, `DRxPRI`) are active in base mode.
- Secondary channels (`DTxSEC`, `DRxSEC`) are enabled via `txsecEn`/`rxsecEn`.
- In secondary mode, host software must interleave TX samples and de-interleave RX samples consistently with lane ordering.
- Reference SPORT guidance indicates reduced maximum practical serial clock when dual-lane mode is enabled.

### 5.4 Host Configuration and Data Movement

- Host writes RX/TX config registers to set channel enable, frame-sync mode, polarity, and transfer-count fields.
- Host uses the FIFO data address to push/pull SPORT payload data.
- Configuration writes are blocked when corresponding lock bits are set.
- `rx_int` is software-driven from RX configuration and can be used as an external interrupt/status indicator.

## 6. Implementation Details

### 6.1 Clock-Domain Structure

The design uses three clocks:

- `wb_clk_i` for host configuration/data access,
- `txclk` for transmit sequencing and serial output,
- `rxclk` for receive sequencing and serial input capture.

Configuration fields from the Wishbone interface are sampled into TX and RX clock domains before use by serial state machines.

### 6.2 TX/RX Control Organization

- Separate TX and RX state machines implement framed serial word transfer.
- TX and RX frame-sync outputs are generated from state-machine phase signals and mode bits.
- TX datapath includes selectable bit-order serialization.
- RX datapath includes primary and secondary serial shift capture.

### 6.3 FIFO and Bus Interface Organization

- `fifo_sport` provides FIFO buffering with separate read/write clocks.
- `wb_interface_sport` implements host decode, handshake outputs, configuration register storage, and FIFO read/write enables.
- FIFO depth and data width are compile-time controlled through `sport_defines.v` and associated macros.

## 8. Clock and Reset

- `wb_rst_i` is the top-level reset source and is used by host interface and serial logic reset paths.
- `txclk` and `rxclk` drive the transmit and receive SPORT domains independently.
- `wb_clk_i` drives host register/FIFO control logic.
- Configuration signals are re-timed into TX/RX domains before controlling serial state machines.

## 9. Constraints

- Compile-time macros select bus width and SPORT data-path width (default in `sport_defines.v`: `WB_WIDTH32` and corresponding SPORT width selection).
- FIFO depth is compile-time configured by ``SPORT_FIFODEPTH``.
- Correct dual-lane operation requires software-level data interleaving/de-interleaving consistency.
- Frame-sync and count programming should ensure valid framing intervals for selected word sizes.
