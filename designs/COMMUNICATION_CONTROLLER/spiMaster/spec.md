# spiMaster Design Specification

## 1. Introduction

`spiMaster` is an SPI master IP core with an 8-bit slave host interface and dedicated support for SD/MMC card initialization and 512-byte block transfers.

The core supports three software-visible transaction classes:

- direct single-byte SPI transfer,
- SD card initialization,
- SD block read/write.

The design uses separate host-bus and SPI logic clocks, programmable SPI clock delay control, and independent 512-byte transmit and receive FIFOs for block data movement.

## 3. Interface

### 3.1 Top-Level Ports

| Signal | Direction | Width | Description |
| --- | --- | --- | --- |
| `clk_i` | Input | 1 | Host/bus clock domain for register access and FIFO host-side access. |
| `rst_i` | Input | 1 | Host reset input. Reset request is synchronized internally to bus and SPI domains. |
| `address_i` | Input | 8 | Host register/FIFO address. |
| `data_i` | Input | 8 | Host write data bus. |
| `data_o` | Output | 8 | Host read data bus. |
| `strobe_i` | Input | 1 | Host transfer strobe. |
| `we_i` | Input | 1 | Host write enable (`1` = write, `0` = read). |
| `ack_o` | Output | 1 | Host transaction acknowledge. |
| `spiSysClk` | Input | 1 | SPI logic clock domain. |
| `spiClkOut` | Output | 1 | SPI serial clock output generated by the SPI wire engine. |
| `spiDataIn` | Input | 1 | SPI serial data input (MISO). |
| `spiDataOut` | Output | 1 | SPI serial data output (MOSI). |
| `spiCS_n` | Output | 1 | Active-low SPI chip select output. |

### 3.2 Host Access Semantics

- Address space is split into control/status registers (`0x00` range), RX FIFO region (`0x10` range), and TX FIFO region (`0x20` range).
- `ack_o` is generated by the host interface decode block.
- Reads of FIFO data registers (`0x10` and `0x20`) use delayed acknowledge behavior in the implementation to align read timing with FIFO access.
- Transaction completion is software-polled via `TRANS_STS_REG[0]` (`TRANS_BUSY`); there is no top-level interrupt output.

| Bit | Name | Access | Description |

#### `TRANS_STS_REG` (`0x04`)

| Bit | Name | Access | Description |
| --- | --- | --- | --- |

| --- | --- | --- | --- |

### 4.3 Data and Address Fields

#### `DIRECT_ACCESS_DATA_REG` (`0x06`)

- Write: transmit byte for direct-access SPI transaction.
- Read: receive byte captured from last completed direct-access SPI transaction.
- SPI bus transfers are full-duplex: each transmitted byte shifts in one receive byte.

#### `SD_ADDR_*` (`0x07` to `0x0A`)

- Forms 32-bit SD card address used by SD block read/write transaction engines.
- Documentation notes SD accesses are typically aligned to 512-byte boundaries.

#### `SPI_CLK_DEL_REG` (`0x0B`)

- Programs SPI wire-engine clock delay after initialization completes.
- Documented relation: `SPI_CLK_DEL = (spiSysClk / (2 * SPI_CLK)) - 1`.

### 4.4 FIFO Region Fields

#### `RX_FIFO_DATA_REG` (`0x10`)

- Read pops one byte from RX FIFO.
- Used primarily for SD block-read payload extraction.

#### `RX_FIFO_DATA_COUNT_MSB/LSB` (`0x12`/`0x13`)

- Combined 16-bit RX FIFO occupancy count.

#### `RX_FIFO_CONTROL_REG` (`0x14`)

| Bit | Name | Access | Description |
| --- | --- | --- | --- |
| `0` | `FIFO_FORCE_EMPTY` | W (self-clearing pulse) | Clears RX FIFO contents. |

#### `TX_FIFO_DATA_REG` (`0x20`)

- Write pushes one byte into TX FIFO.
- Used primarily for SD block-write payload loading.

#### `TX_FIFO_CONTROL_REG` (`0x24`)

| Bit | Name | Access | Description |
| --- | --- | --- | --- |
| `0` | `FIFO_FORCE_EMPTY` | W (self-clearing pulse) | Clears TX FIFO contents. |

## 5. Function Description

### 5.1 Transaction Model

All operations are initiated through the same control sequence:

1. Program mode in `TRANS_TYPE_REG`.
2. Program required mode-specific registers (direct data byte, SD address, FIFO payload, clock delay).
3. Write `TRANS_CTRL_REG.TRANS_START = 1`.
4. Poll `TRANS_STS_REG.TRANS_BUSY` until deasserted.
5. Check `TRANS_ERROR_REG` fields relevant to the selected mode.

### 5.2 Direct Access Mode (`TRANS_TYPE = DIRECT_ACCESS`)

- Provides a single-byte SPI transfer path for generic SPI access.
- Software writes transmit data to `DIRECT_ACCESS_DATA_REG`, then starts transaction.
- The control block drives one TX byte into the SPI wire engine, waits for receive-ready, then completes.
- The received byte is read back through `DIRECT_ACCESS_DATA_REG`.

### 5.3 SD Initialization Mode (`TRANS_TYPE = INIT_SD`)

Initialization behavior follows the documented SD startup sequence:

- The init engine sets a slow SPI clock phase for startup signaling.
- It emits startup clock bytes (`0xFF`) before command exchange.
- It issues CMD0 and checks for expected reset response.
- It then issues CMD1 in a retry loop until card-ready response or timeout condition.
- On completion, the engine returns to ready state and reports `SD_INIT_ERROR` code.
- Normal post-init SPI clock delay is sourced from `SPI_CLK_DEL_REG`.

### 5.4 SD Block Write Mode (`TRANS_TYPE = RW_WRITE_SD_BLOCK`)

- Intended payload size is one 512-byte block.
- Host preloads TX FIFO with block data and programs SD block address registers.
- Engine issues write command (CMD24), sends start/data tokens, streams data from TX FIFO to SPI wire path, appends CRC placeholder bytes, then evaluates card write response and busy-release behavior.
- Error outcomes are reflected in `SD_WRITE_ERROR`:
  - command response failure,
  - data response timeout/error,
  - busy-release timeout/error.

### 5.5 SD Block Read Mode (`TRANS_TYPE = RW_READ_SD_BLOCK`)

- Engine issues read command (CMD17), then polls incoming bytes until data token detection or timeout.
- After token reception, it clocks and captures one 512-byte data block from SPI input.
- Received bytes are pushed into RX FIFO and read by host through `RX_FIFO_DATA_REG`.
- Error outcomes are reflected in `SD_READ_ERROR`:
  - command response failure,
  - read-token timeout/error.

### 5.6 Completion and Chip Select Behavior

- `TRANS_BUSY` is asserted while an operation is active and deasserted when the selected operation returns to idle.
- `spiCS_n` is active low during active command/data phases.
- Top-level `spiCS_n` is derived from internal operation-specific chip-select intents, allowing the active transaction engine to control bus selection.

## 6. Implementation Details

### 6.1 Architectural Organization

The top-level module integrates:

- host bus decode/mux (`spiMasterWishBoneBI`),
- control/status register block with cross-domain synchronization (`ctrlStsRegBI`),
- transaction dispatcher FSM (`spiCtrl`),
- shared command/response engine (`sendCmd`),
- SD initialization engine (`initSD`),
- SD block read/write engine (`readWriteSDBlock`),
- byte-level SPI wire engine (`readWriteSPIWireData`),
- TX/RX byte exchange arbitration (`spiTxRxData`),
- dual-clock TX/RX FIFO wrappers (`sm_TxFifo`, `sm_RxFifo`).

### 6.2 Control Path and Mode Dispatch

- `spiCtrl` receives `TRANS_TYPE` and a synchronized start pulse.
- It dispatches exactly one request path at a time:
  - direct access write-enable path,
  - SD initialization request,
  - SD block read/write request.
- It drives `TRANS_BUSY` while waiting on mode-specific ready conditions.

### 6.3 Shared TX/RX Byte Arbitration

- `spiTxRxData` arbitrates multiple transmit producers with fixed priority and presents one-byte `txDataOut`/`txDataFull` handshake to the SPI wire engine.
- Receive data from the wire engine is latched with `rxDataRdy`; clear strobes from controller blocks release the ready flag.
- This shared path allows direct-access, command, and SD engines to use one SPI serial backend.

### 6.4 SPI Wire Engine

- `readWriteSPIWireData` consumes one TX byte when available, shifts out serial data on `spiDataOut`, samples `spiDataIn`, and asserts receive-ready on byte completion.
- Serial clock rate is set by `clkDelay`; each SPI bit phase is delayed by the programmed count.
- Continuous-byte behavior is supported when the next TX byte is already available.

### 6.5 FIFO Architecture and Clock Crossing

- TX and RX FIFOs are dual-clock buffers (`sm_fifoRTL`) between `clk_i` host domain and `spiSysClk` SPI domain.
- FIFO force-empty control pulses are generated in host domain and synchronized into SPI domain.
- FIFO count exposure is implemented for RX FIFO host-side monitoring.
- FIFO RTL notes no overrun/underrun protection logic beyond full/empty status reporting; software flow control is required.

### 6.6 Reset Implementation

- External `rst_i` and software reset register writes feed reset generation in `ctrlStsRegBI`.
- Bus-domain reset is stretched and SPI-domain reset is derived through synchronization stages.
- Transaction/control/FIFO interface blocks consume synchronized resets in their respective clock domains.

## 7. Submodule List

### 7.1 `spiMasterWishBoneBI`

Role: top-level host interface decode, read-data mux, and acknowledge generation.

Key interfaces:

| Signal Group | Description |
| --- | --- |
| `address`, `strobe_i`, `writeEn`, `ack_o` | Host transaction decode and acknowledge control. |
| `ctrlStsRegSel`, `rxFifoSel`, `txFifoSel` | Region select outputs to downstream blocks. |
| `dataFromCtrlStsReg`, `dataFromRxFifo`, `dataFromTxFifo` | Read-data sources selected by address window. |

### 7.2 `ctrlStsRegBI`

Role: register file implementation and synchronization bridge between `clk_i` and `spiSysClk` domains.

Key outputs include transaction type/start control, SD address, direct-access TX byte, clock-delay setting, and synchronized resets.

### 7.3 `spiCtrl`

Role: transaction-mode controller FSM for `DIRECT_ACCESS`, `INIT_SD`, and SD block operations.

Provides mode request strobes, busy status, direct-access TX trigger, RX-ready clear control, and operation-level chip select control.

### 7.4 `sendCmd`

Role: SD command serializer and response waiter.

Transmits command byte + four argument bytes + checksum byte and returns response byte with timeout indication.

### 7.5 `initSD`

Role: SD card initialization sequencer.

Generates startup clocks, issues CMD0/CMD1 handshake sequence, tracks initialization error coding, and selects initialization SPI clock behavior.

### 7.6 `readWriteSDBlock`

Role: 512-byte SD block read/write sequencer.

Interfaces with command engine, shared SPI byte path, and host-facing TX/RX FIFOs to execute CMD17/CMD24 flows and set block read/write error codes.

### 7.7 `readWriteSPIWireData`

Role: low-level SPI serial byte engine.

Produces `spiClkOut`/`spiDataOut`, samples `spiDataIn`, and provides byte-complete receive events.

### 7.8 `spiTxRxData`

Role: shared one-byte TX/RX staging between controller clients and the wire engine.

Arbitrates transmit requests and centralizes receive-ready/data distribution.

### 7.9 `sm_TxFifo` and `sm_RxFifo`

Role: dual-clock FIFO wrappers for 512-byte host payload buffering.

- `sm_TxFifo`: host writes payload data; SPI domain reads for block write.
- `sm_RxFifo`: SPI domain writes received payload data; host reads for block read.

## 8. Clock and Reset

- `clk_i`: host register/FIFO bus interface clock.
- `spiSysClk`: SPI protocol/control datapath clock.
- The design explicitly crosses control/data between these domains using synchronization and dual-clock FIFO structures.
- Reset behavior is driven by `rst_i` and software reset requests; reset effects are synchronized per domain before use by local logic.

## 9. Constraints

- SD block transfer architecture and software programming model assume 512-byte block transactions.
- SD address programming should respect storage addressing constraints; documentation recommends 512-byte boundary alignment for block accesses.
- Software must respect FIFO occupancy/fullness constraints; the FIFO core does not provide full protocol-level overrun/underrun protection.
- Correct operation depends on configured `spiSysClk`/`clk_i` relationships and timing assumptions used by the synchronization scheme.
