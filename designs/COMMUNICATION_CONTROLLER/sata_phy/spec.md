# sata_phy_top_x6series Design Specification

## 1. Introduction

`sata_phy_top_x6series` implements the SATA PHY layer boundary between a SATA link-layer interface and an external GT transceiver interface. The module supports host or device behavior through parameterization and provides link bring-up control, primitive handling, and data transfer bridging.

The design does not include serialization/deserialization or 8b/10b codec logic. Those functions are provided by the external transceiver, which is controlled through the GT-side interface signals.

## 3. Interface

### 3.1 Parameters

| Parameter | Type | Description |
| --- | --- | --- |
| `DATA_BITS` | Integer | Link-side data width. The delivered design and documentation use 32-bit link words. |
| `IS_HOST` | Integer | Mode select: `1` = host PHY behavior, `0` = device PHY behavior. |
| `SATA_REV` | Integer | SATA revision selector used for timing/counter presets: `1`, `2`, or `3`. |

| Signal | Dir | Width | Description |
| --- | --- | --- | --- |
| `clk` | Input | 1 | Link-layer AXI-Stream clock domain. |
| `clk_phy` | Input | 1 | PHY/transceiver control and datapath clock domain. |
| `rst_n` | Input | 1 | Active-low reset for PHY logic and CDC FIFOs. |
| `lnk_tx_tdata_i` | Input | `[DATA_BITS-1:0]` | Link-layer transmit data toward PHY. |
| `lnk_tx_tvalid_i` | Input | 1 | Link-layer transmit source-valid. |

| `lnk_rx_tready_i` | Input | 1 | Link-layer receive ready. |

| `gt_rx_disp_err_i` | Input | `[1:0]` | Receive disparity error indicators. |

| `gt_rx_elec_idle_i` | Input | 1 | Receive electrical-idle indication. |

| `gt_tx_elec_idle_o` | Output | 1 | Requests transceiver transmit electrical idle. |
| `gt_tx_com_strt_o` | Output | 1 | Pulse to start COM sequence transmission. |
| `gt_tx_com_type_o` | Output | 1 | COM type select: `0` = COMRESET/COMINIT, `1` = COMWAKE. |

### 3.3 Interface Semantics

| Interface Group | Semantic Notes |
| --- | --- |
| Link TX AXI-Stream (`lnk_tx_*`) | A transmit beat is accepted when `lnk_tx_tvalid_i` and `lnk_tx_tready_o` are both high in the link clock domain. |
| Link RX AXI-Stream (`lnk_rx_*`) | Receive beats are presented with `lnk_rx_tvalid_o`; transfer completion is controlled by `lnk_rx_tready_i`. |
| GT control/status | COM handshake and OOB/link initialization behavior are coordinated through `gt_tx_com_*`, `gt_tx_elec_idle_o`, and `gt_rx_status_i`. |
| Status output | `phy_status_o[0]` mirrors internal link-up state generated by host/device control logic. |

## 4. Function Description

### 4.1 Functional Scope

The module performs three top-level functions:

1. Executes SATA PHY link initialization and readiness control in host or device mode.
2. Bridges link-layer AXI-Stream traffic to/from the transceiver-side datapath across two clock domains.
3. Detects/propagates primitive and receive-error metadata for link-layer processing.

### 4.2 Operating Modes

Mode is selected by `IS_HOST`:

- `IS_HOST = 1`: host control FSM is instantiated.
- `IS_HOST = 0`: device control FSM is instantiated.

Both modes drive:

- link-up indication (`link_up`, exported as `phy_status_o[0]`),
- COM control outputs (`gt_tx_com_strt_o`, `gt_tx_com_type_o`, `gt_tx_elec_idle_o`),
- PHY-generated transmit primitives used during bring-up.

### 4.3 Host-Mode Bring-Up Sequence

In host mode, the control sequence is organized around COMINIT/COMWAKE/ALIGN detection and timeout-controlled retries:

1. Wait for transceiver reset completion (`gt_rst_done_i`) and initial COM transmission completion status.
2. Wait for remote COMINIT detect (`gt_rx_status_i[2]`), then wait for COMINIT deassertion.
3. Send COMWAKE (`gt_tx_com_type_o=1` with start pulse), then wait for remote COMWAKE detect/deassertion (`gt_rx_status_i[1]`).
4. Wait for ALIGN primitive reception; if ALIGN is not observed before timeout, restart link initialization.
5. Transmit ALIGN primitives, then transition to ready after observing required non-ALIGN progression.
6. In READY state, assert link-up and maintain SYNC primitive transmission from the PHY control path when applicable.

Host mode returns to reset/retry flow on timeout conditions or receive electrical idle indication.

### 4.4 Device-Mode Bring-Up Sequence

In device mode, the control sequence responds to host COMRESET and performs COMINIT/COMWAKE/ALIGN progression:

1. After reset completion and absence of COMRESET detect, send COMINIT (`gt_tx_com_type_o=0` with start pulse).
2. Wait for host COMWAKE detect/deassertion (`gt_rx_status_i[1]`), with retry timeout protection.
3. Send COMWAKE (`gt_tx_com_type_o=1` with start pulse).
4. Send ALIGN primitives until remote ALIGN is observed; if ALIGN is not observed before timeout, enter error then restart.
5. In READY state, assert link-up and continuously drive SYNC primitive from control logic.

At any time, COMRESET detection (`gt_rx_status_i[2]`) forces the device control FSM back to reset state.

### 4.5 Transmit Datapath Behavior

Transmit behavior is partitioned into pre-link and post-link phases:

- Before link-up, transceiver transmit data/charisk are driven by the selected PHY control FSM (OOB and training primitives).
- After link-up, link-layer AXI-Stream data is transferred through a CDC FIFO into the PHY clock domain and serialized from 32-bit link words into 16-bit transceiver words.

Key TX behavior:

- `axis_fifo_36W_16D` bridges `clk` to `clk_phy` for `{tdata,tuser}`.
- Internal transmit-ready pacing in `clk_phy` controls beat consumption and lower/upper halfword progression.
- `lnk_tx_tuser_i` bits are forwarded to transceiver K/D outputs during link-layer driven transmission.

### 4.6 Receive Datapath Behavior

Receive behavior aligns 16-bit transceiver samples into 32-bit link words and propagates metadata:

1. Incoming GT data, K indications, and error flags are shifted in `clk_phy`.
2. ALIGN primitive detection selects one of two 32-bit word alignments.
3. Aligned 32-bit data, 4-bit K information, and 4-bit error information are registered.
4. A receive-valid strobe is generated in the PHY domain and used as AXI-Stream valid into the RX CDC FIFO.
5. `axis_fifo_40W_16D` transfers receive payload and sideband from `clk_phy` to `clk`.

At the link-layer output:

- `lnk_rx_tdata_o` carries aligned data.
- `lnk_rx_tuser_o[3:0]` reports primitive/data qualifier bits.
- `lnk_rx_tuser_o[7:4]` reports receive byte error indicators.

### 4.7 Link Completion and Status

Link completion is represented by internal `link_up` from the selected host/device controller and exported as `phy_status_o[0]`.

- `phy_status_o[0] = 1`: link is in controller READY state.
- `phy_status_o[0] = 0`: link is not established or controller is in initialization/recovery state.

## 5. Implementation Details

### 5.1 Architectural Partitioning

The top-level implementation is organized into:

- Host/device PHY control FSM block (`sata_phy_host_ctrl_x6series` or `sata_phy_dev_ctrl_x6series`).
- TX CDC and serialization path (`axis_fifo_36W_16D` plus TX muxing).
- RX alignment and metadata extraction path (shift registers, alignment-select muxes, valid generation).
- RX CDC path (`axis_fifo_40W_16D`).

### 5.2 Control Path and Bring-Up Timers

Both control FSMs use `SATA_REV` to select counter presets for retry and alignment windows:

- Retry window: nominal 10 ms class counter preset.
- Host ALIGN wait window: nominal 873 us class preset.
- Device ALIGN wait window: nominal 55 us class preset.

These counters gate state transitions for retry/recovery and link-up progression.

### 5.3 TX Path Realization

The TX path includes two independent selection dimensions:

- Source domain crossing and buffering through TX AXI FIFO.
- Word-lane selection between lower and upper 16-bit halves for transceiver output.

A registered multiplexer stage drives `gt_tx_data_o` and `gt_tx_charisk_o` in `clk_phy` domain. During bring-up, PHY control primitives drive the transceiver. After link-up, link-layer payload/primitive stream drives the transceiver path.

### 5.4 RX Path Realization

The RX path uses shift registers and two-way alignment selection to form 32-bit words from incoming 16-bit transceiver data. Primitive detection (`ALIGN`) controls alignment selection. K-character and error vectors are aligned with payload words, then exported to the link layer through the RX AXI FIFO.

### 5.5 Status Mapping

`phy_status_o` is mapped from the internal link-up indicator:

- `phy_status_o = {7'b0, link_up}`.

## 7. Clock and Reset

### 7.1 Reset Behavior

- `rst_n` is active low.
- Control FSM state, link-up indication, and internal datapath control registers are reset when `rst_n` is asserted.
- TX and RX AXI CDC FIFOs use `s_aresetn` driven by `rst_n`.

### 7.2 Clock Domains

- `clk`: link-layer AXI-Stream domain.
- `clk_phy`: transceiver-side PHY control and data alignment domain.
- TX and RX traffic crosses these domains through dedicated AXI FIFOs.

### 7.3 Reference Clocking by SATA Revision

| `SATA_REV` | `clk` | `clk_phy` |
| --- | --- | --- |
| 1 | 37.5 MHz | 75 MHz |
| 2 | 75 MHz | 150 MHz |
| 3 | 150 MHz | 300 MHz |

## 8. Constraints

- An external SATA-capable transceiver must provide and consume GT interface signals as defined in Section 3.
- `gt_rx_status_i` bit semantics must match COM status definitions for correct bring-up sequencing.
- AXI-Stream handshake semantics are required on link TX and RX interfaces.
- The provided implementation is documented for 32-bit link data operation (`DATA_BITS=32`).
- Valid `SATA_REV` settings are `1`, `2`, and `3`.
